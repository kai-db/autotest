# GPT-6 适配变更说明

2026-09-08：在本项目覆盖已安装 Skills 的过度流程限制；保留领域知识、接口契约和实际权限要求。原始全局与插件文件不修改，避免影响其他项目和被插件升级覆盖。

# 项目 Skills 适用规则

本文件由 `AGENTS.md` 引用，属于项目约定。用户当前指令在项目规则与 Skills 之间优先，且不改变系统、开发者及工具权限层级。已授权、信息足够就直接执行。

## 选择与冲突裁决

1. 用户点名的 Skill 优先；否则依据任务目标选择最少的相关 Skills。未使用的 Skills 不加载正文；技术引用只按需阅读，不递归加载全部依赖。
2. 同名 Skill 只选一个入口：明确点名的路径优先；未点名时，内置/官方插件优先于旧个人副本；Android 同内容双份优先 `~/.agents/skills/`。若内容有实质差异，按当前任务、证据新鲜度和宿主工具能力判断，不能只看目录名。
3. 删除本项目执行流程中的无条件“先问用户”“禁止自行决定”“每步等批准”。Skill 的确认步骤先检查是否已有对应授权；已有授权且目标/风险未改变时，完成核验后继续。
4. 需要额外授权时，先把结果做成可审阅的草案，再只询问缺失的范围或决定。引用实际读取的 `SKILL.md` 路径、具体条款及其适用原因；不能把自己的谨慎偏好冒充硬性要求。
5. 领域前置条件继续执行：查询真实 API/schema、验证鉴权、读取危险清单、检查写入对象、验证视觉结果等。“确认数据正确”优先由工具检查，并不等于“让用户确认”。
6. 外部发送、发布、不可逆覆盖、凭据注入和权限扩展按已有授权与宿主边界处理。只读请求不包含写入授权；不得因某个 Skill 提到发布就扩大任务。
7. Skill 名称、模型版本、工具名及调用方式与宿主不一致时，使用当前可验证的能力；缺少可选工具可选择等效方案并说明。真正缺少鉴权/外部能力时报告阻塞，不伪造执行。

## 对已发现冲突的项目覆盖

| Skill / 规则组 | 本项目执行方式 |
|---|---|
| `using-superpowers` | 取消会话开头必调、1% 相关性阈值和强制连锁加载；按实际任务选择。 |
| `brainstorming` | 用户要求探索方案或需求确实不清时用于设计；明确的修改请求直接做，不先走逐题访谈或无条件设计批准。 |
| `writing-plans` / `executing-plans` | 多步骤任务自主维护简短计划并执行；不为每个步骤停工，不自动 commit。缺依赖或测试失败先诊断可修原因；不把局部问题升级为整个任务停摆。 |
| `using-git-worktrees` | 根据现有改动与隔离需要自行选择；不重复询问已授权的工作区操作，不覆盖未提交改动。 |
| `test-driven-development` / `writing-skills` | 测试强度随行为风险；配置/文档用静态验证即可，不为仪式删除已有实现，不为低影响维护强制红绿测试或压力子代理实验。用户明确要求 TDD/评估时照办。 |
| `subagent-driven-development` / `dispatching-parallel-agents` / `requesting-code-review` | 有独立且有价值的工作，并且宿主允许委派时才使用；产品修复的 reviewer 按 agent-dev-loop 执行，不再叠加重复评审。 |
| `finishing-a-development-branch` | 验证后直接交付变更与结果；不强制让用户从收尾菜单选择，不自行 merge、push、创建 PR 或丢弃工作。 |
| `receiving-code-review` / `systematic-debugging` | 核对证据、定位根因并修复授权范围内的问题；普通疑点自行查证。无法安全选择的实质冲突才询问，不把一次失败当作必须人工接管。 |
| `agent-dev-loop` | 范围按 AGENTS.md 第 5 条；保留产品修复的独立 review 和实际状态约束。已有任务续跑，不重复建 task/plan；复用已有批准，不伪造框架要求的授权记录。 |
| `gh-fix-ci` / `gh-address-comments` | 用户要求修 CI/处理评论且范围清楚时直接分析修复；取消例行“先批准修复计划”或重复选择评论。身份登录与明确未授权的外部操作单独处理。 |
| `adaptive` / `agp-9-upgrade` / `migrate-xml-views-to-jetpack-compose` / `styles` / `testing-setup` | 可从项目取得版本、布局、依赖和测试证据时自主查证；已授权的迁移不推回给用户手工完成。引入超出原任务的迁移/实验 API 时先完成独立工作，再明确提出范围变化。 |
| `figma-generate-library` / `figma-code-connect-components` | 范围和目标明确时自主完成并用截图/映射核验，取消每页、每组件固定等批准；目标冲突、破坏性覆盖或未授权发布仍需具体决定。保留 figma-use 的 API 前置要求。 |
| `security-threat-model` / 产品规划顾问类 | 用证据和显式假设完成报告；有信息缺口时标明结论限制，不强制访谈后才交付。用户要求工作坊时才使用逐轮问答。 |
| `openai-docs` | 优先当前内置入口，官方资料核验后执行用户请求；缺少 MCP 时采用可用官方文档查询路径，不为查文档自动安装 MCP 或要求重启。 |
| `imagegen` / `pdf` / 文档与表格插件 | 使用适合当前工具的单一入口；保留视觉/数据验证与凭据边界，已授权的普通操作不重复确认。不擅自降低用户指定模型/输出要求。 |
| `lark-*` / `writing-daily-weekly-reports` | 遵守用户全局 lark-cli、Kai 用户身份、固定 Android 表及全量任务口径。已明确的身份、目标、日期和授权直接复用；保留分页、真实 ID、最小 OAuth scope 与危险覆盖检查。摘要默认上限不替代用户要求的全量。 |
| `sites-*` / `loopx-*` / 其他外部服务 Skills | 保持任务边界；工具提供发布/发送能力不代表用户授权。现有工具硬门禁与账户权限仍有效。用户指定只读或本地交付时，不自动扩展为外部写入。 |

## 生效范围

这是项目行为覆盖，不是卸载或隐藏 Skill。当前会话的目录不会因编辑文件即时变化；新会话重新读取项目规则。宿主若把 Skill 使用要求作为更高层级指令注入，以宿主要求为准，并明确披露仍存的冲突。

本机 Codex 源码的 `skill_config_rules_from_stack` 只接受 User / SessionFlags 层的启停规则，因此本项目不使用无效的 `[[skills.config]]`。如未来要实际减少全局目录，需要另行按用户指定的作用域调整全局配置；不能把“项目级清理”扩大成所有项目的配置修改。
