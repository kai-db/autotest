# AI 驱动测试机制（v1.6 新增子系统总览）

> 版本：v1.0 | 创建日期：2026-06-12
> 定位：说明 v1.6 落地的六大机制如何把「AI 探索」和「确定性回归」焊接起来。
> 设计来源：midscene.js（缓存回放）、Healenium（指纹自愈）、Maestro（AI 软断言）、
> Marathon（统计重试）、Kaspresso（双链拦截器）、AppAgent（知识沉淀）、Mobile-Agent（pre-action 比对）。

## 0. 总架构：agentic authoring + deterministic execution

```
        AI 在环（探索/首跑/修复）                 确定性执行（回归/CI）
┌─────────────────────────────────┐      ┌─────────────────────────────────┐
│ Claude Code + mobile-mcp         │      │ autotest AAR（Espresso/UiAutomator）│
│  · 看屏幕、规划、判定             │ 产出  │  · 零 LLM 依赖                    │
│  · 读 app-knowledge/ 再上手      │─────►│  · CaseCacheStore(READ_ONLY) 回放 │
│  · 产出 CachedCase 缓存 + 知识库  │      │  · SelfHealingLocator 兜底       │
│  · 注入 AiLocatorFallback/断言器  │◄─────│  · 报告回流：自愈事件/AI断言/根因  │
└─────────────────────────────────┘ 回流  └─────────────────────────────────┘
```

**原则**：LLM 只在 authoring 阶段在环；execution 阶段所有 AI 接口（AiLocatorFallback /
AiAssertionEvaluator）不注入，框架自动降级为确定性行为并留痕。

## 1. 三级自愈定位（selector 包）

```kotlin
val spec = byResId("com.app:id/btn_login") or byText("登录")
locator.find(spec).click()
```

降级链：**确定性 BySelector → 指纹自愈（HealingEngine 加权相似度，零成本）→ AI 兜底（可选注入）**。

- 定位成功自动回写 `fingerprints.json` 指纹库
- 非确定性命中产生 `LocatorEvent`，自动进 HTML 报告「定位自愈事件」section
- **铁律：自愈命中必须人工确认**——可能是真实 UI 回归，确认后回填选择器

## 2. 固化桥：缓存回放（bridge 包）

AI 黑盒探索跑通一条用例后，产出 `docs/testing/cache/<caseId>.cache.json`（CachedCase），
回归时框架直接回放，全程零 LLM：

```kotlin
val store = CaseCacheStore(cacheDir, CacheMode.READ_ONLY)  // CI 用只读保证确定性
val case = store.load("TC-S-001")!!
CacheReplay.toScenario(case, UiReplayExecutor(device, locator), collector, interceptors).run()
```

- 模式：READ_WRITE（探索期）/ READ_ONLY（CI）/ WRITE_ONLY（强制重探索）
- 缓存里的 target 是元素快照，回放时经 toSelectorSpec() 走三级自愈，元素微调不破缓存
- 稳定后再把缓存固化为手写 Kotlin Scenario（docs/07 决策③ 的两步走）

## 3. AI 软断言（assertion 包）

```kotlin
aiAsserter.assertWithAi("当前页面应显示钱包余额")                  // 软断言（默认）
aiAsserter.assertWithAi("不应出现红色报错弹窗", optional = false)  // 硬断言
```

- 软断言 FAIL 只告警 + 记录，不挂测试（防 LLM 抖动打爆 CI）
- 无评估器（CI）自动记 SKIPPED 留痕
- 结果进 HTML 报告独立「AI 断言」section，与确定性断言分开统计
- **只用于确定性断言写不出来的场景**（视觉状态/canvas/RN 动态文案），是兜底不是主路径

## 4. 统计化稳定性（stability 包）

```kotlin
val history = TestHistoryStore(File(dir, "test-history.json"))
@get:Rule val retry = RetryRunner(
    adaptivePolicy = AdaptiveRetryPolicy(history, targetSuccessRate = 0.95, maxRetries = 3),
    history = history
)
```

- 重试预算按历史通过率计算（1-(1-p)^n ≥ T）：稳定用例 0 预算、flaky 用例足额、上限封顶
- 每轮尝试是独立统计样本，自动回写历史库
- `FlakyClassifier.registerRule { ... }` 注册项目特化规则（如：支付类超时强制 HARD_FAIL）

## 5. 双链拦截器（intercept 包）

- **watcher 链**（Interceptor）：日志/截图/性能/内存/logcat，纯旁路，永不影响结果
- **behavior 链**（BehaviorInterceptor）：失败恢复，按注册序尝试，恢复成功重试一次
- DialogDismissInterceptor 双角色：beforeStep 预扫 + 失败后再扫（中途弹出的弹窗）

## 6. 失败根因 + 证据链（diagnosis/report 包）

失败时报告自动包含：截图 + logcat + **根因签名**（LogcatAnalyzer 识别 crash/ANR/OOM/native）
+ flaky 分类 + 自愈事件。AI 修复阶段（Phase 4）直接读 `report.json` 的结构化根因，不翻原始日志。

## 7. AI 测试 session 标准开场

1. 读 `docs/testing/app-knowledge/`（页面元素 + 已知弹窗 + **dangerous-ops.md**）
2. 读 `docs/testing/TEST_GUIDE.md` 铁律（危险操作 pre-action 比对）
3. preflight：设备在线 / App 已装 / 测试环境 + 已登录
4. 有缓存的用例优先回放缓存，只对新用例做探索
5. 探索产物三回写：知识库（人读）、用例缓存（机器回放）、TEST_CASES.md（规格）
