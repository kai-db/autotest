## 4. 测试策略

采用三层证据闭环：

1. **源码与 JVM 层**：验证纯状态机、并发、租约、认证世代、BTC 聚合器、熔断器；
2. **单设备真实 App 层**：验证真实 UI、后端登录、切钱包、创建账号、登出重登、后台清理；
3. **双设备层**：验证同账号多端登录、IM kicked 状态、重连和 token 重验联动。

设备按最低可行层级选择：

| 层级 | 用途 |
|---|---|
| L1 普通模拟器 | UI、创建账号、切钱包、BTC 登录、后台重启、冒烟 |
| L2 root 模拟器 | 网络故障注入、确定性失败窗口、必要的只读数据探针 |
| L3 三星测试环境真机 | 同账号多端被踢、模拟器网络结论复核 |

小米正式环境真机只允许只读观察，不参与账号和钱包操作。

## 5. 用例架构

两个重写后的 `cases.md` 按以下能力域组织；每条包含变更来源、前置状态、步骤、机器化 oracle、
优先级、设备、复原动作和危险操作标注。

### A. 构建与归因基线

- 记录 DeBox HEAD、提交范围、暂存/未暂存/未跟踪改动清单和工作区 diff 指纹；
- 运行目标模块 JVM 测试、编译门禁；
- 现场构建 APK，记录 sha256、versionCode、签名摘要和运行时行为探针；
- `adb install -r` 前确认签名一致且不降级，禁止卸载兜底；
- 核验设备、AVD 名、测试环境、登录身份、网络 fake-IP 噪声。

### B. HTTP 与 IM 可观测性

- 真实 connect refused/timeout 的 `call_id` 一一关联；
- `network_phase`、耗时和固定原因码；
- 日志脱敏与成功请求事件白名单；
- 业务错误与网络错误分离；
- JIM 冷启动 episode、断网恢复 episode 和 navi host 脱敏。

### C. token 失效与认证恢复

- `TOKEN_OVERDUE(-2007)`、`ACCOUNT_VALIDA(-2018)`、`NEED_AGAIN_LOGIN(-2023)`；
- 高频重复错误同周期只产生一次 `revalidate_episode_start`、一次 LoginOut 和一次有效登录；
- 本地钱包三种错误均自动重新取 message、重签并恢复；
- TP/WC 重验签名成功但 `app_login` 失败时重新展示验证入口；
- 成功登录后门禁重开，下一失效周期可重新进入；
- 旧认证世代回包不得再发布账号失效事件、写 token 或污染新钱包；
- CacheService 首次鉴权失败拉闸，同世代后续同步停止，换代后恢复且不跨账号落库。

无法由真实后端稳定制造的错误码竞态，必须由 JVM/harness 给出确定性证据；不得用普通断网冒充
token 失效。

### D. 钱包登录与生命周期

- 本地私钥钱包登录；
- 助记词钱包的 EVM/SOL/TRON/BTC 派生与登录；
- BTC 桥终态先到、5 秒兜底先到两条路径均只能派发一次 `app_login`；
- BTC 派生结果可迟到落库，但切钱包或新 attempt 接管后旧结果不得落库；
- 同钱包短时间重复登录合并，不重复换认证世代或广播 LoginOut/LOADING；
- 登录进行中切换到另一钱包，旧钱包回包不得覆盖当前账号；
- UI 切钱包后身份、资产遮罩、IM 和业务数据均切换到目标账号；
- 创建账号后的首次登录、重启后仍选择新账号；
- 登出后重新登录，旧进程状态不残留；
- 不覆盖删除最后一个钱包，因为本轮授权未包含删除钱包。

### E. 后台清理与重启

- App 前后台切换、`am force-stop` 冷启动和 Splash 后台 cache cleanup；
- `setNull()` 从后台线程发起时 teardown 在主线程完成；
- 旧实例的签名任务、HTTP/BTC 回调在 teardown 后不写全局认证态、不发 SUCCESS/FAIL；
- 新实例可正常登录，`wallet-sign` 线程不泄漏；
- 全程无 crash、ANR、SUCCESS→FAIL 反转或重复登录风暴。

### F. 账号被踢与多端恢复

- 同账号在两台测试环境设备登录，观察 Rong/JIM
  `KICKED_OFFLINE_BY_OTHER_CLIENT`；
- 被踢设备给出正确提示，不产生无限 IM 重连或 `app_login` 风暴；
- 前台恢复、重新登录或切回账号后 IM 建立新 episode；
- 若多端登录同时导致服务端 token 失效，归入 C 组 oracle 验证，而不是只看 UI toast；
- 区分账号被其他客户端踢下线与群/语音房踢人，本轮只测前者。

### G. 回归冒烟

- 冷启动、消息、朋友、发现、我的；
- 登录后数据和 IM 可用；
- 无新增 FATAL/ANR/ERROR 风暴；
- 保留与本次提交范围直接相关的 Sol `call_id` 接线验证；
- 分享二维码历史增量移出本轮主目标，不再占用账号认证 run 的验收结果。

## 6. 结果与证据

两个 `results.md` 都从模板重建，不复制旧首轮、Round 5 或待执行结论。两个 run 尚未纳入 git，
旧结果不会被误称为“已由 git 留档”；按用户“测试结果全部重来”的要求直接替换，不在新正文中混合。

每条用例至少记录：

- 实际设备和 AVD 名；
- 起止时间、操作状态和复原状态；
- PASS/FAIL/BLOCKED/NOT_RUN；
- 日志文件、截图或机器化命令输出；
- 请求次数、唯一 epoch/call_id、错误码和关键状态转移；
- 失败根因是否属于产品、环境、夹具或不可达条件。

敏感字段只做是否为空、数量和固定枚举断言，不写 token、签名、地址全文、助记词或私钥。
