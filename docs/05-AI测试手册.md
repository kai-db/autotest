# AI 测试手册

> 供 Claude Code / Codex 阅读。通过 mobile-mcp 操控真机执行 Android App 自动化测试。
> 框架侧机制（缓存回放/自愈定位/软断言/历史重试）见 [docs/09](09-AI驱动测试机制.md)。

## 0. Session 开场必读（每次测试前）

1. **读知识库** `docs/testing/app-knowledge/`：
   - `dangerous-ops.md` —— 危险操作清单，**点击前比对，命中先停**（详见 §4）
   - `screens/*.md` —— 已沉淀的页面元素表/已知弹窗，避免重复探索
2. **读铁律** `docs/testing/TEST_GUIDE.md` 第二节（登录态/测试环境只用不破坏）
3. **查缓存** `docs/testing/cache/`（如有）：已缓存的用例优先按缓存步骤回放，只对新用例做探索

## 1. 角色与工作流

你是 Android App 测试助手，用户用自然语言下指令，你自主完成测试。

```
理解意图 → 读知识库 → 确认设备 → 启动App → 执行操作 → 关键节点截图验证 → 输出结论 + 回写产物
```

## 3. 操作指南

### 测试前检查

```
1. mobile_list_available_devices → 确认设备在线
2. mobile_get_screen_size → 记住屏幕尺寸（滑动用）
3. mobile_launch_app → 启动目标 App
4. mobile_take_screenshot → 确认启动状态，处理弹窗
```

### 处理弹窗

```
mobile_list_elements_on_screen → 找到按钮 → 点击
  权限弹窗 → "允许" / "Allow"
  升级弹窗 → "跳过" / "以后再说" / "取消"
  引导页   → "跳过" / "Skip" / "进入"
```

### 点击

```
mobile_list_elements_on_screen → 找到坐标 → mobile_click_on_screen_at_coordinates
备选：截图观察位置 → 估算坐标 → 点击
```

### 输入

```
点击输入框（获取焦点）→ mobile_type_keys
```

### 滑动

```
下滑：startY=高度*3/4, endY=高度/4（屏幕中线 x=宽度/2）
上滑：startY=高度/4, endY=高度*3/4
```

### 按键

```
返回：mobile_press_button button: "BACK"
Home：mobile_press_button button: "HOME"
```

## 4. 操作规则

- **关键节点截图**：用例开始、页面跳转后、验证点、失败时。不需要每步都截图
- **操作前先 list_elements**，不盲猜坐标
- **遇到弹窗先处理**
- **操作失败时截图分析原因**，不盲目重试
- **操作间隔至少 1 秒**
- **不假设页面状态**，看截图/元素列表再行动

### 危险操作比对（每次点击前，钱包 App 专项）

目标元素文本/语义命中 `app-knowledge/dangerous-ops.md`（转账确认/签名授权/删除钱包/
登出/清数据/切环境/导出私钥等）时：**不点击**，截图记录 → 核对用例是否明确要求 →
未要求则规避并记入 results.md。另外三条绝对禁令：

- ❌ `clearAppData` / `pm clear` / 卸载重装（丢登录态 + 切回正式环境）
- ❌ 登出 / 切换环境
- ❌ 私钥/助记词页面截图（截图会留存敏感信息）

### 探索产物回写（每轮测试收尾）

| 产物 | 位置 | 内容 |
|---|---|---|
| 知识库 | `app-knowledge/screens/<页面>.md` | 新确认的元素定位、新弹窗、跳转关系（按模板） |
| 危险操作 | `app-knowledge/dangerous-ops.md` | 新发现的危险入口 |
| 用例缓存 | `docs/testing/cache/<caseId>.cache.json` | 跑通用例的步骤序列（CachedCase 格式，见 docs/09 §2），供回归零探索回放 |
| 结果 | `runs/日期-功能/results.md` | 本轮结果 + 证据 |

## 5. 监工模式与铁律

> 完整的监工模式流程（Phase 1-6）、铁律、Bug 修复原则、文件约定见 [TEST_GUIDE.md](testing/TEST_GUIDE.md)。

### 单条用例执行流程（速查）

```
1. 重置：mobile_terminate_app → mobile_launch_app → 处理弹窗
2. 执行：按 cases.md 步骤操作，操作间隔 ≥1 秒
3. 验证：关键节点截图 + list_elements 检查 + 确认 App 未崩溃
4. 判定：PASS 或 FAIL（附截图和原因）
5. 收口：PASS 记一行即走；FAIL 走 ①抓原始日志线路 ②三分类 A产品/B埋点/C判据
   ③agent-dev-loop「分析记录模式」登记（≤10min，**不改代码**）→ 立刻下一条
   ⛔ 不在遍历中途切进修复
```

**判 FAIL 先分类,别急着修**（`TEST_GUIDE.md` §5.3）：A=产品行为错 → 修产品；
B=行为对但日志记错 → **只改埋点**；C=判据写错对象 → **只改 cases.md，禁碰产品代码**。
分类要用**独立于被质疑信号**的证据（例：疑「重复建连」就数底层 socket 事件，别数应用层埋点条数）。

**防卡死**：单条 >15min 无进展判 `FAIL-超时`；崩溃/元素缺失各重试 1 次即判定；
命中危险操作直接记「已规避」不问人。8 类卡点完整预案见 [TEST_GUIDE.md](testing/TEST_GUIDE.md) 第五节。

## 6. 输出格式

### 单条用例

```
TC-001 冷启动 [P0] → PASS
TC-003 手机号登录 [P0] → FAIL
  失败步骤: 输入手机号 → 输入框未响应
  截图: screenshots/tc003_fail.png
  根因: 输入框被遮挡层覆盖
```

```
  修复: TC-007 滑动无响应 → 增加等待时间
第2轮: PASS 12 / FAIL 0
验收: PASS 12 / FAIL 0 ✅
```
