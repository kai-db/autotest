# 系统架构文档

> Android AutoTest v1.8.2 — 框架 + Claude Code + mobile-mcp 自动化测试体系

## 1. 系统全景

```
┌──────────────────────────────────────────────────────────────┐
│                      用户（开发/测试）                         │
│                   "帮我测一下登录流程"                         │
└───────────────┬──────────────────────────────────────────────┘
                │
    ┌───────────▼───────────┐
    │   Claude Code / Codex  │  AI 大脑
    │   理解意图 → 规划步骤   │  生成测试 → 分析结果
    └───────────┬───────────┘
                │ 调用 MCP 工具
    ┌───────────▼───────────┐
    │   mobile-mcp Server    │  设备桥接
    │   截图/点击/输入/滑动   │  adb 封装
    └───────────┬───────────┘
                │ adb 命令
    ┌───────────▼───────────┐
    │   Android 真机/模拟器   │  运行 DeBox App
    │   com.tm.security.wallet│
    └───────────────────────┘

    ┌───────────────────────┐
    │   autotest AAR 库      │  CI 自动化回归
    │   Espresso + UiAutomator│  固定用例 + 报告
    │   通过 Gradle 执行      │
    └───────────────────────┘
```

## 2. 两条测试路线

### 路线 A：AI 交互式测试（Claude Code + mobile-mcp）

```
用户自然语言 → Claude Code 理解 → mobile-mcp 操控真机 → 截图分析 → 判定结果
```

### 路线 B：CI 自动化回归（autotest 框架）

```
git push → CI 触发 → Gradle connectedAndroidTest → autotest 执行 → JSON/HTML 报告
```

### 闭环

```
AI 发现 bug → 固化为 autotest 用例 → 加入 CI → 每次发版自动回归
```

## 3. 设计来源与技术基底

autotest 不是直接 fork 某个开源项目，而是在 Android 官方测试栈之上做的轻量封装：

| 层次 | 来源/参考 | 在本项目中的体现 |
|---|---|---|
| 底层测试能力 | AndroidX Test + Espresso + UiAutomator | `EspressoExt`、`UiAutomatorExt`、`BaseUiTest`、`DeviceActions` |
| 框架设计参考 | Kaspresso | `TestCase`、`BaseScenario`、`flakySafely`、双链拦截器、设备 API、Logcat/弹窗处理 |
| AI 黑盒测试层 | Claude Code / Codex + mobile-mcp | 自然语言规划、截图理解、点击/输入/滑动、结果判定 |
| 缓存回放（固化桥） | midscene.js | `bridge/`：CachedCase + CaseCacheStore（三模式）+ CacheReplay |
| 定位自愈 | Healenium / Appium AI 插件生态 | `selector/`：指纹库 + 加权相似度自愈 + 三级降级链 |
| AI 软断言 | Maestro assertWithAI | `AiAsserter`：optional 默认软断言 + 独立报告通道 |
| 统计化重试 | Marathon | `AdaptiveRetryPolicy` + `TestHistoryStore` 历史通过率预算 |
| 知识沉淀 / 危险操作比对 | AppAgent / Mobile-Agent | `docs/testing/app-knowledge/`（元素表 + dangerous-ops 清单） |
| 项目扩展 | autotest 自研封装 | `MonitorMode`、Markdown 用例解析、JSON/HTML 报告、根因分类、DeBox 测试闭环文档 |

> v1.6 各机制的使用方式与降级语义见 `docs/09-AI驱动测试机制.md`。

Kaspresso 对本项目影响最大的不是具体代码复制，而是测试框架形态：

- `TestCase` 参考 Kaspresso TestCase 的 before/run/after 四段式组织方式。
- `BaseScenario` 参考 Kaspresso BaseScenario，把常见步骤组封装为可复用场景。
- `flakySafely` 和 `RetryRunner` 参考 Kaspresso 的 flaky 重试思路，但当前实现更轻量。
- `InterceptorChain` 参考 Kaspresso BehaviorInterceptor / WatcherInterceptor 思路，用于统一处理日志、截图、弹窗、性能和 logcat。
- `DeviceActions` 参考 Kaspresso Device API，把 adb shell、权限、网络、屏幕和 App 管理收敛到统一入口。
- `DialogDismissInterceptor` / `LogcatInterceptor` 分别参考 Kaspresso 的系统弹窗处理和 logcat dump 能力。

本项目的差异点是：Kaspresso 主要服务白盒 UI 自动化回归；autotest 在此基础上增加了面向 DeBox 的 AI 黑盒探索路线，希望形成“AI 探索发现问题 → 固化为 Espresso/UiAutomator 用例 → CI 回归”的闭环。

## 4. autotest 框架模块全景

```
com.autotest（19 个模块）
│
├── 测试基础层
│   ├── base/           BaseUiTest + BaseActivityTest（集成自愈定位 + AI 断言注入点）
│   ├── config/         TestConfig + ConfigLoader + Environment（多环境）
│   ├── data/           TestDataManager + TestAccount（测试数据）
│   └── util/           EspressoExt + UiAutomatorExt + WaitUtil + MonotonicTime + ScreenshotRule + TestArtifacts
│
├── 操作与断言层
│   ├── action/         AppActions（Tab 切换、引导页跳过）
│   ├── assertion/      AppAssertions + AiAsserter（AI 软断言，评估器外部注入）
│   └── device/         DeviceActions（网络/权限/屏幕/App/Logcat）
│
├── 定位与固化桥层（v1.6 新增，详见 docs/09）
│   ├── selector/       SelectorSpec 复合选择器 + HealingEngine 指纹自愈 + SelfHealingLocator 三级降级
│   └── bridge/         CachedCase 用例缓存 + CaseCacheStore（三种模式）+ CacheReplay 回放
│
├── DSL 与执行引擎层
│   ├── dsl/            Scenario + Step + BaseScenario（stepIf/flakyStep/repeat/forEach 数据驱动）
│   └── engine/         TestRunner + TestSuite + MonitorMode（轮次超时保护）+ TestCaseParser
│
├── 拦截器与生命周期层
│   ├── intercept/      InterceptorChain 双链（watcher 观察 + behavior 失败恢复）
│   │   ├── LoggingInterceptor       操作/步骤自动日志（watcher）
│   │   ├── ScreenshotInterceptor    失败自动截图，可缩放压缩（watcher）
│   │   ├── PerformanceInterceptor   耗时阈值告警 + P50/P95 百分位（watcher）
│   │   ├── MemoryInterceptor        每步 PSS 采集 + 泄漏告警（watcher）
│   │   ├── LogcatInterceptor        失败自动收集设备日志（watcher）
│   │   └── DialogDismissInterceptor 弹窗关闭（纯 behavior 失败恢复；watcher 链保持纯旁路契约，P0-1）
│   └── lifecycle/      TestLifecycleHook + Manager
│
├── 安全层（v1.7 新增）
│   └── safety/         DangerousOpsGuard 危险操作点击网关（铁律#7 代码层：全部点击入口统一过闸，
│                       fail-closed 阻断 + 截图留证 + 词表配置注入）+ GuardRegistry + GuardedElement
│
├── 诊断与报告层
│   ├── diagnosis/      LogcatAnalyzer（crash/ANR/OOM 根因签名）
│   ├── report/         RunReport + ReportCollector + HtmlReporter（AI 断言/自愈/守卫/根因独立呈现）+ ReportWriter
│   └── runner/         RunnerInfo + DeviceSelector
│
└── 稳定性层
    └── stability/      FlakyClassifierApi + DefaultFlakyClassifier（规则构造注入，不可变）+ RetryRunner
                        + AdaptiveRetryPolicy + TestHistoryStore（历史通过率）+ FlakySafely + WaitPolicy
```

## 5. 各模块职责

| 模块 | 职责 | 核心类 |
|---|---|---|
| base | 测试基类：集成拦截器+日志+生命周期+自愈定位+AI 断言注入点 | BaseUiTest, BaseActivityTest, TestCase |
| config | 分层配置 + 多环境管理 | TestConfig, ConfigLoader, ConfigKeys, Environment |
| data | 测试数据：按环境区分的账号/自定义数据 | TestData（含 TestDataManager + TestAccount） |
| util | Espresso/UiAutomator 扩展 + 等待 + 单调计时源 + 截图 Rule + 产物清理 | EspressoExt, UiAutomatorExt, WaitUtil, MonotonicTime, ScreenshotRule, TestArtifacts |
| action | 通用 App 操作封装 | AppActions（Tab 切换、引导页跳过） |
| assertion | 通用断言 + AI 软断言（评估器外部注入，CI 自动 SKIPPED） | AppAssertions, AiAsserter, AiAssertionEvaluator |
| device | 设备能力封装（adb shell） | DeviceActions（网络/权限/屏幕/App/解锁/Logcat） |
| selector | 复合选择器 DSL + 指纹自愈 + 三级降级定位（详见 docs/09 §1） | SelectorSpec, HealingEngine, FingerprintStore, SelfHealingLocator |
| bridge | 固化桥：AI 探索产出用例缓存，回归确定性回放（docs/09 §2） | CachedCase, CaseCacheStore, CacheReplay, UiReplayExecutor |
| dsl | 步骤式 DSL + 可复用场景 + 数据驱动 | Scenario, Steps, BaseScenario（step/stepIf/flakyStep/repeat/forEach） |
| engine | 执行引擎 + 监工模式（轮次超时）+ 用例解析 | TestRunner, TestSuite, MonitorMode, TestCaseParser |
| intercept | 双链拦截器：watcher 观察 + behavior 失败恢复 | InterceptorChain, BehaviorInterceptor, 6 种内置拦截器 |
| lifecycle | 测试生命周期钩子 | TestLifecycle（含 Hook + Manager） |
| log | 统一日志（分级+文件+Logcat） | TestLogger, DefaultTestLogger |
| diagnosis | 失败根因分析（crash/ANR/OOM 签名） | LogcatAnalyzer, RootCause |
| report | 结构化报告（JSON + HTML；AI 断言/自愈事件/根因独立呈现） | RunReport, ReportWriter, HtmlReporter, ReportCollector |
| runner | 设备信息收集 + 选择 | RunnerInfo, DeviceSelector |
| stability | Flaky 规则链 + 自适应重试预算 + 执行历史 | FlakyClassifier, RetryRunner, AdaptiveRetryPolicy, TestHistoryStore, FlakySafely, WaitPolicy |

## 7. 执行引擎数据流

```
TEST_CASES.md
    ↓ TestCaseParser.parse()
TestSuite.loadFromMarkdown()
    ↓ 按 P0→P1→P2 排序
TestRunner.runTest()（每条用例）
    ├── envReset()            铁律6：强制重置环境
    ├── before()              前置操作
    ├── Scenario.run()        DSL 步骤执行
    │   ├── InterceptorChain  拦截器链
    │   │   ├── DialogDismiss  弹窗自动关闭
    │   │   ├── Logging        自动日志
    │   │   ├── Screenshot     失败截图
    │   │   ├── Logcat         失败日志收集
    │   │   └── Performance    耗时警告
    │   └── ReportCollector    收集步骤结果
    ├── after()               后置操作
    └── TestCaseResult        用例结果
    ↓
MonitorMode
    ├── runRound()            Phase 2: 全量测试
    ├── writeResults()        Phase 3: 生成 TEST_RESULTS.md
    ├── recordFix()           Phase 4: 记录修复
    └── runFinalVerification() Phase 6: 最终验收
    ↓
report.json + report.html + TEST_RESULTS.md
```
